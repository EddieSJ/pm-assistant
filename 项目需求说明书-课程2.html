1引言

1.1 编写目的

本文档定义「项目管理智能助手」平台在课程2「数据智能与决策支持」阶段的功能需求、业务规则与约束，作为开发、验收与后续迭代的基准。课程2 的核心目标：在课程1 已建成的「智能文档与知识工作流」基础上，让项目数据从「被记录」走向「能判断」，构建一条可验证的数据决策链——连接数据 → 检查清洗 → 指标分析 → 可视化 → 趋势预测 → 风险预警 → 决策建议与人工确认。

  • 复用（课程1 已实现）：项目全局管理、文件自动识别、项目看板、智能聊天、Word 文档生成、三层记忆（作为工程基础，直接复用与迭代）。

2项目概述

2.1 背景

课程1 已让项目文档「被理解、被沉淀」，但项目经理面对的核心痛点仍在——数据分散（进度、人员、成本、质量、风险各自独立）、口径不一（日期、金额、比例、状态难以直接比较）、更新滞后（看到的多是历史结果）、缺少关联（单张表无法解释问题如何相互影响）。项目管理缺的不是表格数量，而是统一、及时、可关联的判断依据。

表面信号与真实后果之间的四道「误判之门」尤其危险：平均完成率掩盖关键路径失速、尚未超预算掩盖 EAC 持续上升、单表风险正常掩盖跨表叠加、错误对象或口径导致行动落空。最危险的不是缺数据，而是错信数据——错误的确定性，比清晰地承认不确定更危险（详见 7.5）。

2.2 建设目标

在课程1 工程基础上持续迭代，让同一个 Agent 从「知识工作」延伸到「数据决策」：

  1. 连接：七类数据源进入同一视图，项目状态才可能完整。
  2. 治理：数据先治理，才能成为可引用的项目事实。
  3. 判断：指标分析 + 趋势预测 + 风险预警，让「异常」可被及时发现。
  4. 行动：决策建议可分配、可跟踪、可复核，最终由人确认。

2.3 技术栈（概要）

沿用课程1 技术栈（React 18 + Vite 5 ｜ FastAPI ｜ SQLite ｜ 千问 qwen-plus），新增 CSV/XLSX 结构化解析（parsers.parse_table）、EVM 指标引擎、时间快照与预警能力；数据层新增 6 张表（data_sources / clean_logs / snapshots / metrics / alerts / advices）。详见《技术架构.md》。

6.2 指标公式（EVM 挣值管理）

指标引擎基于 EVM 计算，核心公式如下：

  • 进度指标：计划进度（PV）、实际进度（EV）、偏差（EV − PV）、SPI = EV / PV。
  • 成本指标：预算（BAC）、实际成本（AC）、CPI = EV / AC、EAC = BAC / CPI、完工偏差 = BAC − EAC。
  • 人员指标：计划工时、实际工时、加班工时、利用率 = 实际工时 / 计划工时。
  • 质量与风险指标：高级缺陷数、开放风险数、风险分（按风险等级加权）。
  • 工程与采购指标：延期里程碑数、延期交付数、验收状态（通过 / 待验收 / 延期）。

每个指标均可溯源到公式、数据范围与原始记录（见 F-52），不凭空造数、不自动证明因果。已落库指标代码：PV / EV / AC / BAC / SPI / CPI / EAC / completion_dev / progress_plan / progress_actual / progress_dev / plan_hours / actual_hours / overtime_hours / hours_util / high_defects / open_risks / risk_score / delayed_milestones / delayed_deliveries（缺失指标不落库、单独返回 missing）。

列名双语识别（v1.2.0）：真实数据包 CSV 采用英文表头（如 planned_progress / actual_progress / budget_value / actual_cost_value / planned_hours / actual_hours / severity / risk_score / delay_days），指标与清洗引擎的列识别同时支持中英文关键词（datasmart._col、_amount_cols），并严格按「金额列自身的单位列 / 列名」判定金额单位（元 / 千元 / 万元），判不出的记「待确认」且不改值。

口径说明：PV=Σ(预算×计划进度%)、EV=Σ(预算×实际进度%)，故 SPI=EV/PV 反映「实际进度 / 计划进度」；BAC 取成本表预算合计，AC 取成本表实际成本合计，EAC=BAC/CPI。

7业务规则与约束

7.1 数据治理四原则

课程2 数据决策链全程遵循「可控、可追溯、可复核、可比较」四原则：

  1. 可控：原始文件只读，清洗与标准化全程留痕，不悄悄改值；模糊问题标「待确认」由人工确认。
  2. 可追溯：来源标签 + 时间戳审计层，指标 / 预测 / 建议可回到公式、数据范围与原始记录。
  3. 可复核：预测与建议说明方法、基线、限制，输出可复核的行动草案，关键节点待人工确认。
  4. 可比较：多时间节点快照（T1/T2/T3 + 修订号）历史不覆盖，变化趋势可对比。

7.2 决策支持必须回答「发生什么、为什么、怎么办」

  1. 发生了什么：指标、差距与异常（事实）。
  2. 为什么发生：跨表证据与影响路径（解释）。
  3. 现在怎么办：行动、责任、期限与确认（行动）。

只给结论不是决策支持，能解释并能行动才是。

7.3 预警落到「对象、原因、责任人、期限」

每条预警包含对象 ID、证据、责任人、期限与来源。好的预警必须让管理者知道风险在哪里、为什么、由谁处理。

7.4 数据不替代判断

数据与指标仅提供决策支持，最终决策由人负责并人工确认；预测不把不确定写成确定事实；跨表证据不自动宣称因果。

7.5 误判之门（四类失真）

最危险的不是缺数据，而是「错信数据」。四类只看得见的表面信号，会掩盖真实管理代价：

误判之门表面信号（看起来正常）真实后果
① 进度平均完成率掩盖关键路径失速关键路径任务严重滞后，交付延迟不可避免
② 成本尚未超预算掩盖 EAC 持续上升EAC 持续上升，项目最终将超预算
③ 风险单表风险状态均在可接受范围跨表风险叠加形成系统性风险，可能触发连锁影响
④ 责任RACI 表已填写、责任看似清晰错误对象或错误口径导致行动落空、责任被推诿

错误的确定性，比清晰地承认不确定更危险。本平台的应对：七类数据合流 + 跨表证据链 + 指标溯源 + 责任落到对象。

7.6 决策支持四层次

层次回答的问题时间指向
报表已经发生了什么过去（已发生）
监控正在发生什么变化现在
预测按当前趋势可能发生什么未来（可能发生）
决策支持现在应该优先处理什么未来（行动）

真正的价值不是更快生成报表，而是更早形成行动判断。

7.7 预警四步闭环与升级路径

  1. 识别触发条件：进度、成本、质量、人员和采购异常。
  2. 形成证据链：关联受影响的任务、里程碑和责任人。
  3. 评估风险等级：明确影响范围与升级路径（正常 / 关注 / 高风险）。
  4. 生成行动建议：设置责任、期限与人工确认。

越早预警，越有机会把损失控制在发生前；风险管理的价值不是解释失败，而是为提前干预争取时间。

7.8 分层架构（向下控制、向上创造管理价值）

层内容
决策层行动建议、期限、替代方案与人工确认
预警层风险等级、影响对象与责任边界
趋势层多时间节点、变化速度与预测

数据层Excel / CSV 与项目业务对象
