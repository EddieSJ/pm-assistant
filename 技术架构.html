项目管理智能助手 — 技术架构

版本 v0.3.0 更新 2026-10-11 React + FastAPI + SQLite + 千问 本地单端口 8000

私人本地部署的项目管理智能体 Web 平台，通过外部 env 接入大模型 API，自动识别项目文件夹中的各类文档，提取关键信息并沉淀到本地记忆体，实现「有据可依、有理有据、有记忆、有标准」的项目管理中枢。

2系统架构

采用「前端 — 后端 — 数据 — 模型」四层结构，单端口（8000）部署（图见顶部「系统架构总览」）。

课程资料根目录（PM_ASSISTANT_BASE_DIR 指向）
  ├── 02_千问API与env配置/.env   ← 环境变量 / API Key（绝不入仓）
  ├── 03_本地知识库/            ← 企业知识（注入系统提示）
  ├── 04_文件处理约束库/         ← 文件处理约束（注入系统提示）
  ├── 05_当前任务记忆体/         ← memory_schema + 任务记忆 JSON
  └── 06_项目输入资料包/         ← 待识别的项目原始文件

关键设计原则：代码与数据分离。pm-assistant/ 只放代码与本文档；课程资料（.env、知识库、约束库、记忆体、输入包）放在上一级目录，运行时通过环境变量 PM_ASSISTANT_BASE_DIR 注入。

4后端模块设计

4.1 config.py — 配置层

  • 用 BACKEND_DIR.parent 定位项目根目录；BASE_DIR 默认 parent.parent，可用环境变量 PM_ASSISTANT_BASE_DIR 显式覆盖（支持代码与资料分离）。
  • .env 优先从 BASE_DIR/.env 读取，回退旧结构 02_千问API与env配置/.env。
  • 暴露 Config 类：LLM 参数、行为开关（source_trace / require_human_approval）、目录配置。
  • ensure_dirs() 在 import 时创建运行时目录；has_api_key() 供 health 接口判断连通性。

4.2 db.py — 数据层

  • 标准库 sqlite3，check_same_thread=False + threading.Lock 保证并发安全。
  • _SCHEMA 一次性建 12 张表；_migrate() 做向后兼容的轻量字段补充。
  • 提供 query()（读）与 execute()（写）两个统一入口。

4.3 llm_client.py — 模型接入

  • 对接 DashScope 千问 OpenAI 兼容接口（/chat/completions）。
  • chat() 非流式；chat_stream() 流式逐块 yield（当前无调用方，保留供后续）；extract_json() 稳健剥除代码围栏后解析 JSON。
  • API Key 仅从 Config.api_key 读取，绝不落日志。

4.4 parsers.py — 文件解析

  • parse_file() 按扩展名分派：.md 直读、.pdf PyMuPDF、.docx python-docx、.xlsx openpyxl。
  • SUPPORTED_EXTS = {.md, .pdf, .docx, .xlsx, .txt}，其余走 read_text 兜底。
  • 前后端支持的扩展名清单需保持同步（后端 parsers.SUPPORTED_EXTS，前端 ProjectModal.SUPPORTED）。

4.5 knowledge.py — 知识注入

  • 加载 03_本地知识库 与 04_文件处理约束库 下所有 .md，拼接为系统提示文本。
  • knowledge_text() / constraints_text() 供 L1 系统指令使用。

4.6 memory.py — 三层记忆

记忆层表用途
工作记忆memories_working写入并在下一轮回读最近 N 条（默认 8 条）参与上下文
任务记忆memories_task对齐 memory_schema.json，回写 JSON
长期记忆memories_longterm沉淀项目知识 / 结论 / 标准（key-value）

4.7 agent.py — Agent 编排核心

  • 指令三层：L1 系统指令 + L2 工作流指令（analyze / answer / docgen）+ L3 任务指令。
  • _analyze_single_file()：单文件 → LLM 识别类型 + 提取结构化信息，失败时返回兜底结构不抛断流水线。
  • 单文件注入 LLM 有 MAX_FILE_TEXT = 12000 字符截断上限。
  • _analyze_worker()：后台线程遍历项目文件夹，逐文件分析并写入各表。
  • 分析为「追加写入」模式，重复点击会累积重复数据，需删除项目重建清零。
  • answer()：聊天回答，执行「找 → 核 → 写 → 追」全链路，关键词打分召回（Top-K 截断）。
  • 分析进度保存在进程内内存字典 _jobs，服务重启即丢失、不跨 worker。
  • sanitize()：正则过滤身份证 / 手机号 / 银行卡 / API Key 四类敏感信息。

4.8 doc_gen.py — 文档生成

  • markdown_to_word()：按标题 / 列表逐行转 .docx；Markdown 表格行按纯文本段落保留。
  • build_summary_markdown()：基于看板数据生成项目综合整理报告 Markdown。

事实状态枚举：confirmed（已确认）/ provisional（待核实）/ needs_confirmation（待确认）。

所有业务表以 project_id 普通列关联；删除项目时由应用层显式按 11 张子表名单 DELETE 级联，数据库层未声明外键约束。

6核心机制

6.1 找 · 核 · 写 · 追

  1. 找：回读工作记忆历史（默认最近 8 条）+ 关键词打分召回检索相关项目事实 + 长期记忆，拼装上下文。
  2. 核：结论必须基于已确认事实，严格区分「事实 / 推断 / 待确认」。
  3. 写：调用 LLM 生成回答，标注来源。
  4. 追：行动项追踪 + 记忆沉淀。

6.2 证据链

文件 → 证据 → 事实 → 判断 → 行动 → 记忆沉淀

每个结论标注 [来源: 文件名]；sources 表留存原文内容用于追溯。单文件注入 LLM 上限 12000 字符。

6.3 四道门

事实门（有据）→ 结构门（条理）→ 可用性门（可落地）→ 风险门（不越权、标记「需人工复核」）。

6.4 授权-停下

缺关键材料 / 结论不可验证 / 权限不足 / 事项未确认 → 主动停下并说明，绝不编造。（系统提示词层的输出纪律约束，非代码层强制拦截。）

6.5 敏感信息过滤

输出前正则过滤身份证（18 位）、手机号、银行卡 / 长数字、API Key（sk- 前缀），不写入记忆。

8前端架构

  • App.jsx：以 view 状态在「项目列表 / 项目看板」间切换，无路由（单页两级视图）。
  • api.js：统一 fetch 封装，错误抛出后端 detail 信息。
  • ProjectList：项目卡片 + 全局统计卡。
  • ProjectModal：新建 / 编辑项目，内置目录浏览选择器。
  • ProjectBoard：9 个标签页（概览看板 / 事实台账 / 干系人 / 财务 / 行动项 / 冲突待确认 / 来源文件 / 文档 / 项目智能助手）。
  • Dashboard：KPI 指标卡 + Recharts 图表（财务柱状图、干系人饼图、事实状态饼图）+ 冲突风险清单。
  • ChatPanel：Markdown 渲染回答，标注来源，Enter 发送 / Shift+Enter 换行。
  • 前后端支持的扩展名清单需保持同步（后端 parsers.SUPPORTED_EXTS，前端 ProjectModal.SUPPORTED）。

10安全设计

  1. 凭据隔离：API Key 仅存于本地 .env，绝不硬编码 / 打印 / 落库 / 上传。
  2. 敏感信息过滤：输出前正则隐藏身份证 / 手机号 / 银行卡 / API Key，且不写入记忆。
  3. 授权边界：AGENT_REQUIRE_HUMAN_APPROVAL=true，Agent 只准备草稿与整理结果。
  4. 人工复核标记：财务 / 合同 / 人事结论一律标记「需人工复核」。
  5. 本地化部署：localhost 单端口，数据全在本机。
  6. 已知待加固：下载接口 filename 未做路径穿越（..）校验，依赖本地单用户部署前提。
  7. CORS 放宽：allow_origins=["*"] 全开放，暴露公网前需收紧。
