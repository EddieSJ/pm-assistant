# 课程3 模拟数据包 · 计划与资源智能调度

> 用途：为「项目管理智能助手」课程3「计划与资源智能调度」提供**可解析、可验证**的未来约束材料，用于演练 文件效力识别 → WBS 映射 → 五类约束 → 确定性排程 → 多视图呈现 → 资源负荷与冲突 → 关键路径 → 版本派生与方案比较 → 人工确认 的完整闭环。
> 数据性质：**全部为教学虚构数据**，企业、人员、供应商、金额均为虚构，不涉及真实主体。
> 生成方式：`pm-assistant/tools/gen_course3_dataset.py`（日期与工期由工作日历计算，可复现）。
> 对应需求：`pm-assistant/项目需求说明书-课程3.md`（F-63~F-90）。

## 二、与课程2 数据的衔接

本数据包不重复课程2 的事实底座，通过 ID 对齐复用：

| 关联对象 | 课程2 数据包（`02_模拟数据包/`，状态日 2027-03-31） | 课程3 数据包 |
|---|---|---|
| 项目 | `project_id = CY-DCM-2026-01` | 同 |
| 任务 | `T01`~`T15`（工作进度表） | 活动 `A401`~`A427` 各自归属 `T05`~`T15` |
| 人员 | `P001`~`P010`（人员工时表） | 沿用并补充 `P011`~`P013` |
| 里程碑 | `M01`~`M10`（工程里程碑表） | 沿用，并新增活动级里程碑 `MS-A411` / `MS-A423` / `MS-A427` |

**关键衔接点**：

| 衔接项 | 课程2 记录 | 课程3 对应 |
|---|---|---|
| P004 苏槿利用率 131% | 人员工时表 `utilization_rate = 131%` | B01c 04-06 并发需求 10.5h ÷ 可用 8h = 131.2%（一致） |
| M08 用户验收通过 | `forecast_or_actual_finish = 2027/5/4` | A427 最终验收预测 = `2027-05-04`（一致） |
| M10 生产上线 | `forecast_or_actual_finish = 2027-05-07` | 课程3 重排后 A423 生产切换 = `2027-04-29` |
| T10 集成测试 62%、T11 UAT 38%、T13 上线准备 12% | 工作进度表实际进度 | A409/A410（T10）、A414~A417（T11）、A411~A413/A423（T13）为其剩余工作 |

> **关于 5/7 与 4/29 的差异（重要）**：`M10 = 2027-05-07` 是课程2 的**趋势外推口径**（管理预测），对应 PPT 第 27 页 S1 情景的「管理预测约 5 月 7 日」；A423 = `2027-04-29` 是课程3 **约束重排口径**（确定性排程 V1）的结果。两个口径并存不是数据错误，而是课程3 需要解释与确认的核心问题之一。S1 情景「确定性最早约 5 月 5 日」即 V1 结果在扰动后的一天变化。

## 五、数据字典（关键字段）

### A01_项目总控进度计划.csv
| 字段 | 说明 |
|---|---|
| `activity_id` / `task_id` / `wbs_path` | 统一活动编号 / 父任务 / WBS 路径（如 `A4 > A41 > A411`） |
| `owner_resource_id` / `owner_name` | 责任资源（稳定 ID + 姓名） |
| `baseline_start` / `baseline_finish` | **基线日期**：已批准的控制参照 |
| `forecast_start` / `forecast_finish` | **当前预测**：按现状推算的可能结果 |
| `duration_days` | 工期（工作日） |
| `is_milestone` / `milestone_id` | 是否里程碑 / 里程碑编号 |
| `quality_gate` | 关联质量门（`G-UAT` / `G-FAT`） |
| `approval_status` | 进度计划批准状态 |

### A02_各专业剩余工作反馈.csv
| 字段 | 说明 |
|---|---|
| `discipline` | 专业：DG 数据治理 / DEV 开发 / QA 质量保证 / UAT 验收测试 / TRN 培训 / OPS 运维上线 / DOC 文档 / PM 项目管理 |
| `local_id` | 专业本地工作项编号（如 `DG-01`） |
| `mapped_activity_id` | 映射到的统一活动编号（映射而非覆盖，保留本地编号） |
| `duration_estimate_days` | 团队提交的**专业估算**工期 |
| `candidate_resource_ids` | 候选资源（分号分隔） |
| `dependency_statement` / `dependency_type` | 依赖描述 / 类型（`已结构化` 或 `自然语言候选`） |

### B01b_资源每日容量与承诺.csv
| 字段 | 说明 |
|---|---|
| `work_date` | 工作日 |
| `capacity_hours` | 日期区间容量（默认 8h/日） |
| `committed_hours` | 其他已承诺工作（既有承诺） |
| `available_hours` | **可用容量 = 容量 − 已承诺**（资源可用性口径） |

### B01c_活动资源需求.csv
| 字段 | 说明 |
|---|---|
| `demand_role` | 需求角色：`责任` / `支持` |
| `demand_hours_per_day` | 每日需求小时 |
| `confirmation_status` | 资源需求确认状态（`已确认` / `待确认`） |

### B02_关键测试资源借调申请.csv
| 字段 | 说明 |
|---|---|
| `approval_status` | `审批中` / `已批准`——**申请不等于批准** |
| `approved_capacity_hours_per_day` | 已批准容量；`审批中` 时为 `0`，不得计入 V1 正式容量 |
| `effective_condition` | 生效条件 |

### C01 / C02 / C03
| 文件 | 关键点 |
|---|---|
| C01 供应商进场计划 | `commitment_status` = 承诺，但 `precondition` 前置条件未确认前不得进入正式排程 |
| C02 生产窗口通知 | `notice_status=已发布`：已发布的**时间边界**，作为约束而非日期来源 |
| C03 协调会纪要 | `item_type` 区分 `决定` / `行动项` / `讨论项` / `待决事项`——讨论项与待决事项不得当作正式决定 |

### D01~D04（暂不授权）
| 字段 | 说明 |
|---|---|
| `event_authority` | 事件效力：`立即生效` / `条件生效` / `仅情景模拟` / `仅形成比对任务` |
| `required_action` | 对应处理动作（重算 / 模拟 / 记录 / 等待确认） |

## 六、数据检查点（预期被「输入检查七问」捕获）

本数据包刻意保留了**效力层面**的真实问题（而非格式噪声），用于演练输入检查七问：

| # | 检查点 | 位置 | 预期处理 |
|---|---|---|---|
| 1 | P011 何嘉悦同时出现在资源池与借调申请中，但审批未完成 | B01a + B02 | 正式容量为 0，只能进入「批准情景」，不得进入 V1 |
| 2 | A411 对 P004 的资源需求确认状态为「待确认」（来自专业反馈的候选资源） | B01c | 进入 V1 前须人工确认 |
| 3 | 4 条依赖为「自然语言候选」（DG-04、UAT-01、TRN-02、OPS-06） | A02 | 须人工转为结构化依赖，不得直接参与排程计算 |
| 4 | C03 含「讨论项」（DISC-01）与「待决事项」（PEND-01） | C03 | 不得当作正式决定；待决事项不得作为已获批容量 |
| 5 | C01 供应商承诺带前置条件（现场电力与网络准备） | C01 | 前置条件未确认前不进入 V1 正式排程 |
| 6 | P004 在 2027-04-06 ~ 04-08 连续三日并发需求 10.5h > 可用 8h（131.2%） | B01c + B01b | 生成资源冲突预警（对象 / 时间 / 原因 / 证据 / 影响 / 备选处理 / 责任人） |
| 7 | P012 张维汉在 04-19 ~ 04-21 有其他项目既有承诺 2h/日 | B01b | 计算可用性时必须扣除，否则会误判容量 |
| 8 | D 类事件含四类不同效力（立即生效 / 条件生效 / 仅情景模拟 / 仅形成比对任务） | D01~D04 | 分别触发重算 / 模拟 / 记录 / 等待确认，不得一律重算 |

> **「输入检查七问」对照（PPT 第 17 页）**：① project_id 一致性 — 本包全部为 `CY-DCM-2026-01`；② 日期类别 — 见 A01 的 `baseline_*` 与 `forecast_*` 分列，A02 的 `duration_estimate_days`；③ 文件状态 — 见 B02 的 `approval_status`、C01 的 `commitment_status`、C02 的 `notice_status`、C03 的 `item_type`；④ 稳定 ID — `activity_id` / `task_id` / `resource_id` / `milestone_id`；⑤ 依赖完整性 — 见检查点 3；⑥ 容量按日期区间有效性 — 见 B01b；⑦ 来源与确认人可追溯 — 见各文件 `source_material`。
